# Employee Management Application

A full-stack CRUD application for managing employee records. A **Spring Boot** REST API stores data in **MySQL**, and a **React** single-page app provides the user interface.

## Features

- View all employees in a table
- Add a new employee (name, phone, email)
- Edit an existing employee
- Delete an employee

## Tech Stack

| Layer    | Technology                                                        |
| -------- | ----------------------------------------------------------------- |
| Backend  | Java 17, Spring Boot 4.1.2, Spring Web MVC, Spring Data JPA, Lombok |
| Database | MySQL                                                             |
| Frontend | React 18, Vite 5, React Router 6, Axios, Tailwind CSS 3           |

## Getting Started

### 1. Clone the repository

```bash
git clone https://github.com/Ankit-Kumar-71/Employee-Management-Application.git
cd Employee-Management-Application
```

### 2. Set up the database

Create an empty MySQL database:

```sql
CREATE DATABASE employee_data;
```

The `employee` table is created automatically on first run (`spring.jpa.hibernate.ddl-auto=update`).

### 3. Configure and run the backend

Copy the example config into place and fill in your MySQL credentials:

```bash
cd beckend
cp application.example.properties src/main/resources/application.properties
```

Edit `src/main/resources/application.properties`:

```properties
spring.datasource.url=jdbc:mysql://localhost:3306/employee_data
spring.datasource.username=your_mysql_username
spring.datasource.password=your_mysql_password
```

Start the API:

```bash
./mvnw spring-boot:run        # Windows: mvnw.cmd spring-boot:run
```

The API runs at `http://localhost:8080`.

### 4. Run the frontend

In a new terminal:

```bash
cd frontend
npm install
npm run dev
```

Open `http://localhost:5173` in your browser.

## API Reference

Base URL: `http://localhost:8080`

| Method   | Endpoint          | Description           | Body       |
| -------- | ----------------- | --------------------- | ---------- |
| `GET`    | `/employees`      | List all employees    | -          |
| `GET`    | `/employees/{id}` | Get one employee      | -          |
| `POST`   | `/employees`      | Create an employee    | Employee   |
| `PUT`    | `/employees/{id}` | Update an employee    | Employee   |
| `DELETE` | `/employees/{id}` | Delete an employee    | -          |

**Employee JSON**

```json
{
  "name": "Jane Doe",
  "phone": "9876543210",
  "email": "jane@example.com"
}
```

`id` is generated by the database and returned in responses.

**Example**

```bash
curl -X POST http://localhost:8080/employees \
  -H "Content-Type: application/json" \
  -d '{"name":"Jane Doe","phone":"9876543210","email":"jane@example.com"}'
```

## Configuration Notes

- **CORS:** the backend only allows requests from `http://localhost:5173` (set via `@CrossOrigin` in `EmployeeController`). Change it if the frontend runs elsewhere.
- **API URL:** the frontend calls `http://localhost:8080/employees` (set in `frontend/src/Service/EmployeeService.js`). Update it when deploying.
- Do not commit your real `application.properties`; it contains database credentials.

## Known Limitations / Roadmap

- No input validation or duplicate-email check on the backend
- Requesting a non-existent employee ID returns a 500 instead of a 404
- Errors are logged to the console rather than shown in the UI
- API URL and CORS origin are hardcoded rather than environment-driven
- No authentication
